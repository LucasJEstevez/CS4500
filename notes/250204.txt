I/O Devices
-	Device Controller
o	To provide a simple interface of device control to OS
o	Physically controls the device: accepts commands from OS, and carries them out
-	Device driver
o	The software that talks to a controller, giving it commands and accepting responses
Interactions btwn OS and I/O devices
-	The OS gives commands to the I/O devices
-	The I/O device notifies the OS when the I/O device has completed an operation or has encountered an error
-	Data is transferred btwn memory and an I/O device
How I/O Devices Notify the OS
-	Hardware device events
o	Hardware devices produce events at times and in patterns not known in advance
	Keyboard presses
	Incoming network packets
	Mouse movements
o	How to make information generated by these events available to running applications?
	Three methods
•	Polling
•	Interrupt
•	DMA (Direct memory access)
Polling (busy waiting)
-	The I/O device puts information in a status register
-	The OS periodically checks the status register
-	Reading data from an SSD takes tens of microseconds instead of milliseconds as with hard disks
-	Writes are more complicated as they require a full data block to be erased first and take more time
How I/O Devices Notify the OS
-	Polling
o	The I/O device puts info in a status register
o	The OS periodically checks the status register
-	Interrupt
o	Whenever an I/O device needs attention from the processor, it interrupts the processor from what it’s currently doing
-	Direct Mem Access (DMA)
o	A chip that can control the flow of bits btwn memory and some controller without constant CPU intervention
Transition btwn user/kernel mode
-	Interrupt – HW device requests OS services
-	Trap – user program requests OS services: system calls
- A user program needs a system service (reading a file): execute a trap instruction to transfer control to OS
		- OS inspects parameters, carries out system call, returns control to the instruction following the system call
-	Exception – error handling
